# Order Service

REST API for an online store order management system. Built with Laravel, MySQL, and Vue 3.

## Tech Stack

- **Backend:** Laravel
- **Frontend:** Vue 3, Vite, Tailwind CSS
- **Database:** MySQL
- **Authentication:** Laravel Sanctum
- **Testing:** PHPUnit / Pest (via Laravel Artisan)

## Requirements

- PHP 8.2+
- Composer
- Node.js and npm
- MySQL

## Installation & Setup

Follow these steps to run the application locally.

**1. Clone the repository**

```bash
git clone https://github.com/shafaadha/order-service.git
cd REPOSITORY
```

**2. Install PHP dependencies**

```bash
composer install
```

**3. Configure environment**

```bash
cp .env.example .env
```

Update the database configuration in `.env` according to your local MySQL setup.

**4. Generate application key**

```bash
php artisan key:generate
```

**5. Run migrations and seeders**

```bash
php artisan migrate --seed
```

**6. Install frontend dependencies and start the application**

```bash
npm install
composer run dev
```

The application will be available at the local URL displayed in the terminal.

> If `composer run dev` is not configured in `composer.json`, start the backend with `php artisan serve` and the frontend with `npm run dev` in separate terminals.

## Environment Configuration

The repository includes `.env.example` as a template for environment variables.

Example:

```env
APP_NAME="Order Service"
APP_ENV=local
APP_KEY=
APP_DEBUG=true
APP_URL=http://127.0.0.1:8000

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=order_service
DB_USERNAME=root
DB_PASSWORD=

```

Make sure to create the database before running migrations.

**Important:** The actual `.env` file is excluded from version control and must never be committed.

## Order Creation Flow

The `POST /api/orders` endpoint handles order creation and inventory updates.

The request flow is:

1. **Route:** The request enters through `routes/api.php` and passes through the Sanctum authentication middleware.
2. **Controller:** `OrderController@store` receives the request.
3. **Validation:** Validates the customer ID, product IDs, and item quantities.
4. **Database Transaction:** Executes the order creation process inside `DB::transaction()`.
5. **Stock Locking:** Retrieves the requested products using `lockForUpdate()` to prevent concurrent stock modifications.
6. **Stock Validation:** Checks whether each product has sufficient stock. If not, a validation exception is thrown and the transaction is rolled back.
7. **Order Calculation:** Calculates subtotal, 11% tax, and grand total.
8. **Database Storage:** Creates the order and its order items, then decreases the corresponding product stock.
9. **Response:** Returns the created order with its items and HTTP status `201`.

### Order Creation Endpoint

`POST /api/orders`

Example request:

```json
{
    "customer_id": 1,
    "items": [
        {
            "product_id": 1,
            "quantity": 2
        },
        {
            "product_id": 2,
            "quantity": 1
        }
    ]
}
```

Successful response:

```json
{
    "success": true,
    "message": "OK",
    "data": {
        "id": 1,
        "order_number": "INV-20261103-1234",
        "customer_id": 1,
        "subtotal": "150000.00",
        "tax_amount": "17000.00",
        "grand_total": "167000.00",
        "status": "PENDING",
        "items": []
    }
}
```

If an error occurs, such as insufficient stock, the database transaction is rolled back to maintain data consistency.

## API Endpoints

| Method | Endpoint | Description |
|---|---|---|
| POST | `/api/login` | Authenticate user |
| GET | `/api/products` | Retrieve products |
| POST | `/api/products` | Create product |
| PUT | `/api/products/{id}` | Update product |
| DELETE | `/api/products/{id}` | Delete product |
| GET | `/api/customers` | Retrieve customers |
| POST | `/api/customers` | Create customer |
| GET | `/api/orders` | Retrieve order history with filters |
| GET | `/api/orders/{id}` | Retrieve order details |
| POST | `/api/orders` | Create a new order |

Protected endpoints require a valid Bearer Token obtained through login.
